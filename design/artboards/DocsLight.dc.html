Heartbeat protocol

A worker holds no open port. Every few seconds it posts the state of each process it owns, and the Core replies with what it wants those processes to be doing.

The loop

There is exactly one endpoint. The worker sends every process it knows about in a single batch; the Core answers with a desired state for each. Nothing else is exchanged, and the Core never initiates contact.

Response

POST /api/v1/workers/heartbeat
 
{
  "workerName": "billing-jobs",

  "processes": [{
    "name": "nightly-sync",

    "ackToken": 7
  }]
}
Caution
A desiredState of idle means “no command”, never “stop”. Stop is stopping.
Token idempotency

Commands are not matched by comparing states, which would replay on every beat. The Core increments a token on each user command, and the worker acts only when that token is newer than the one it last acknowledged.

Applying a command
1.Compare desiredToken against the stored ackToken.
2.If it is not greater, ignore the command entirely — it is a duplicate.
3.Otherwise apply it, set ackToken to the new value, and report it on the next beat.
